# Agent 開發 Brief：Emergent Experience

你要設計並實作一個以數學、人工生命及群體行為為核心的互動視覺 App。使用者可以在電腦、大屏幕或 Meta/Oculus Quest 2 裡，進入一個隨音樂、說話及參與者互動持續演變的世界。

這是一份獨立需求文件，不要求複製任何現有 App 的程式、版面或完整圖案清單。可以提出自己的視覺設計及技術選擇，但必須保留以下體驗目標和原則。文件描述的是目標與參考接口，不代表所有功能已經完成或所有接口已驗證可用。

## 1. 最重要的產品方向

使用者追求的是：**簡單規則＋局部互動＋初始差異或隨機性，演化成難以預先編排的整體行為。**

例如 Game of Life、鳥群、魚群、黏菌網絡：每個個體只遵循少量規則，整體卻產生生長、聚集、分裂、流動、同步及重組。

- 數學／模擬應是真正驅動畫面的核心，不只是背景裝飾或畫面上的公式文字。
- 不要主要依賴預錄 trippy video、固定動畫、每幀亂數，或單純將同一幅圖不停旋轉及縮放。
- 保留世界的狀態與歷史影響，讓使用者看得見「剛才的介入如何改變接下來的演化」。
- 隨機性可以來自種子、個體差異、探索、環境擾動；不必每一步都抽亂數。確定性規則同樣可以有湧現效果。
- 隨機性要有結構、有界限，避免只剩白噪聲，也避免過強擾動摧毀剛形成的秩序。
- 不承諾有限模擬有字面上的無限新穎性；可以存在穩定態、週期、消亡。提供明確的播種／重生及探索操作。
- 現階段優先考慮視覺效果、臨場感及試玩樂趣。基本資源管理要做好，但不要先用大量時間做長跑優化，或為了保守效能過早犧牲效果。

## 2. 視覺與體驗

希望有持續變化、放大、加速、旋轉、形變、深度、回饋殘影及流暢轉場。這些效果應該配合模擬行為，而非掩蓋它。

核心感受之一是「被魚群或鳥群包圍」：

- 個體存在於前後左右上下，有近遠層次，而非只在面前一塊平面上移動。
- 群體可以從身邊掠過、圍繞、分流、聚集，對吸引點、障礙及使用者動作作反應。
- 將運動規則與外觀分開，同一模擬可以呈現魚、鳥、光點、幾何碎片、線條或抽象生物。
- 支援中央觀察、外部觀察、俯瞰及跟隨等視點。VR 與桌面可採不同預設。
- 讓觀眾能選擇固定觀看一個世界，不能被自動導演強迫一直轉場。
- 畫面控制應簡潔，提供沉浸模式、暫停、重生、強度、速度、色盤及必要的模型控制。可提供公式／規則說明面板。

## 3. 模擬模型方向

第一個可試玩版本優先涵蓋下列核心模型；分階段交付可以，但要清楚列出尚未完成的部分。

| 模型 | 應實作的原理 | 期望觀感／互動 |
| --- | --- | --- |
| Game of Life | 真正同步更新的 B3/S23，清楚定義邊界 | 細胞出生、死亡、移動；可播種及重生 |
| Boids | 分離、對齊、聚合；有界速度與轉向 | 魚群／鳥群包圍、避開、分流與回旋 |
| Physarum 黏菌模型 | 感應痕跡、轉向、沉積、擴散及消退 | 自己編織的光網、分支、通道；使用者放置吸引點 |
| Swarmalators | 個體位置與內在相位互相耦合 | 光群逐漸同步、分群、環形或相位波；適合音樂互動 |

Lenia 是下一個值得加入的候選；Reaction–Diffusion、DLA、Neural Cellular Automata 可列為後續擴充，不要求一次全做。

可以保留或新增 Fourier、Lissajous、超公式、吸引子等數學場景，但不應取代上述湧現模型的產品重心。

規則正確性與視覺化要分開：例如把二維 Life 映射到立體表面，不應稱為真正三維 Life。加入隨機播種、溶解或額外作用力時，清楚標示為創作變體。模型應有可重現的種子或預設，方便比較及除錯。

## 4. 聲音驅動

支援現場麥克風，以及 App 內音樂播放器直接接入音訊分析。播放 Demo 歌時，不應要求使用者用麥克風重新收喇叭聲。

分析可以包含頻段能量、音量包絡、頻譜變化及 onset／節拍估計：

- 快速反應：脈衝、局部大小、局部亮度、短暫加速。
- 數秒變化：密度、探索程度、相位同步、色盤及旋轉趨勢。
- 較慢變化：場景選擇、整體氣氛及轉場。

保留平滑、衰減、門檻及轉場冷卻時間，避免頻繁跳變。音樂盡量改變環境與有界規則參數，讓系統自行演化；不要每一下鼓聲都重置模擬。使用者手動參數與自動調節的關係必須可理解。

麥克風、內置音樂、模擬訊號的來源要清楚標示。處理權限拒絕、裝置中斷、靜音及音源切換，避免雙重播放、回音及重複 AudioContext。

## 5. JEV：場景導演

JEV 是決策層，負責從已定義的選項及範圍中選擇方向，不負責逐幀渲染，也不應直接輸出並執行任意程式碼。

可提供給 JEV 的有界狀態：

- 最近一段音樂特徵摘要、當前場景、已運行時間及最近轉場。
- 使用者明確選擇的偏好、喜歡／不喜歡、強度及希望保留的內容。
- 主持人或觀眾的有效語音／文字請求。
- 多人投票摘要、目前播放曲目及待處理點歌。
- 資源是否已就緒及目前是否離線。

輸出可以包括場景、調色盤、群體行為、強度級別、是否保持目前狀態、是否轉場、是否準備新素材。以 schema、允許清單及數值限制驗證結果；低信心、錯誤、逾時或過期結果不應造成畫面突變。

使用本機插值及模擬執行決策。限制請求頻率及未完成請求數，禁止累積無限佇列。手動選擇優先於遲到的 AI 指令。JEV 失效時，自動導演以本機規則繼續。

不要把音樂特徵、模型信心或觀眾偏好稱為真實情緒或心理狀態的測量。

## 6. 逐字稿、語音指令與觀眾口味

使用者希望使用 Chrome 可用的語音轉文字能力。不要假設網頁能讀取 Chrome「即時字幕」面板；檢查 Web Speech API 或其他明確可用的介面。Quest 瀏覽器與桌面 Chrome 能力可能不同。

- 提供「聽取指令」開關或按住說話，避免把歌詞、閒談全當命令。
- 支援文字輸入及按鈕作替代；可由手機／電腦主持端取得逐字稿。
- 如「慢一點」「讓魚群包圍我」「變成暖色」「不要轉場」應映射到明確操作。
- 暫停、停止及降低強度有直接本機控制，不依賴 JEV 回覆。
- 只保存必要、固定長度的逐字稿及摘要。不要預設整晚錄音或上傳原音。
- 清楚說明哪些辨識／決策會使用雲端，不能將依賴網絡的辨識標示為離線能力。
- 觀眾偏好來自明確選擇、投票或回饋，可在當場逐漸調整；提供重設，不自行建立永久個人檔案。

## 7. 音樂、點歌與生成素材

用 Suno 生成 2–3 首原創、風格／能量不同的 Demo 音樂，下載並整合到播放器，讓使用者直接測試視覺反應。

建議三種對比：低速空靈 ambient、中速有清楚節奏的電子音樂、高能量 psychedelic electronic。安排安靜、漸強、節奏回歸等段落，便於觀察反應。模型提示的 BPM／長度不是實測結果，不要冒充已驗收。

播放器要有曲目選擇、播放／暫停、音量及進度；顯示真實載入／生成狀態。不得用模擬音冒充 Suno 成品。API 任務可能返回多個版本，避免為湊曲目重複付費生成；保存來源、prompt 及任務狀態。

「點歌」至少分兩類：

1. 選播已有歌曲／Demo，直接排入播放佇列。
2. 描述新歌，例如「想要深海感、慢拍、沒有歌詞」，經 JEV 分類並由生成模型背景製作。

生成未完成時繼續現有體驗；完成後由使用者或主持人接受，於合適位置切換或淡入淡出。不承諾精準無縫對拍、即時作曲或可播放任意商業歌曲。歌曲、歌詞及語音轉錄不能自行取得導演權限。

AI 生圖可作紋理、環境背景、粒子外觀素材；圖片不等於完整 3D 模型。生圖與音樂生成是背景任務，不能阻塞動畫。設定生成數量／費用上限、有限佇列及素材快取。生成結果不明時保存 task ID，先查詢，不盲目再次提交付費請求。

## 9. 3D／VR

主要目標裝置是 Meta/Oculus Quest 2。桌面仍需可玩，VR 應有真正雙眼立體、頭部追蹤及周圍空間，而非平面畫面貼在面前。

可以用 Three.js＋WebXR 或其他合適技術，但說明選擇。Quest 2 能力及實際效能必須實測，不以桌面成功代替頭盔驗收。

- 預設保持使用者頭部視點自然，由世界在周圍活動。
- 自動飛行／強制鏡頭移動是明確可選模式，不預設搶控制。
- 提供控制器基本操作、暫停、退出及重設位置；手部追蹤可後續加入。
- 沒有 VR 能力時回退桌面，不讓整個 App 無法使用。
- 頭盔連接電腦服務時，電腦的 localhost 不等於頭盔 localhost；準備正確的 HTTPS／安全來源方案，不靠繞過憑證警告。

## 10. Offline mode

核心模擬、3D 渲染、麥克風分析、已下載音樂及預設導演邏輯應可離線運作。

- 預先快取必要程式及素材，不依賴運行時 CDN；提供「離線資源已就緒」狀態及版本更新機制。
- 斷網不中斷或重設目前模擬，改由本機規則接續。
- JEV、生圖、整歌離線時停用，使用已有素材；不堆積恢復後的大量生成請求。
- 語音離線辨識不能假定支援；不可用時保留文字／按鈕／控制器。
- 重新連線後丟棄過期指令，在合適時間重新啟用 AI。
- 同機互動可離線；同一 Wi-Fi 多人需要本機房間服務，不能等同於完全沒有網絡連線。

## 11. 多人一起玩

支援方向是一個共享房間：主持電腦／大屏幕、手機參加者，以及 VR 參加者。先以同場體驗設計，遠端多人可分階段。

主持人選主音源及整體模式，參加者可投票、點歌、選偏好或操控自己的吸引點。明確決定誰能發出全場語音指令，防止所有人同時搶控制。每人仍可本機降低強度或退出。

同步場景、時間、事件及必要模擬狀態，而非逐幀傳影片。若要求看到同一群體位置，需要權威狀態／校正機制；只共用亂數種子不能保證不同裝置永久同步。處理加入、離開、重連及過期輸入。

## 12. 效果優先，但保留基本資源管理

使用者會親自試玩並回報，不需要先投入大量長跑效能工程。仍要做到：

- 固定容量粒子、重用陣列／幾何、少量重用回饋緩衝。
- 切換場景釋放不再使用的 GPU 紋理、材質及渲染資源。
- 有限的音訊、逐字稿、決策歷史、快取、下載及網絡佇列。
- 停止或離場時清理麥克風、事件監聽、計時器及連線。
- 不以定時強制垃圾回收作設計核心，不重建整個引擎來掩蓋洩漏。

## 13. 建議交付順序與驗收

以短迭代交付可試玩的成果，不要只寫計劃，也不要把未完成的功能包裝成已完成：

1. 本機湧現世界：核心模型、直接音樂分析、2–3 首 Suno Demo、手動及預設導演。
2. 3D 包圍感、多視點、Quest 2 入口及離線核心資源。
3. JEV 導演、明確啟用的語音／文字指令、觀眾偏好及點歌。
4. 背景素材生成與多人共享互動，按使用者試玩回饋調整。

每次交付附啟動方式、試玩步驟、已測與未測內容。至少驗證：

- 規則的代表性例子正確；固定種子可重現，改變種子能產生差異。
- 暫停真的停止模擬；手動模式不被自動／遲到 AI 指令覆蓋。
- 音樂播放器的實際音訊驅動畫面，停止／切源後不留錯誤輸入。
- JEV 失敗及斷網時仍能玩；已快取內容能在離線重新開啟。
- 生成任務重開後可恢復查詢，沒有重複提交或無限排隊。
- VR、真人收音、語音辨識、多人同步及長跑效果，只有實測後才聲稱驗證。

**成功的標準：使用者感到自己進入一個會自行演化、可以影響但不能完全預測的世界；音樂、說話及共同參與讓世界有回應，而不是蓋過它本身的規律。**
